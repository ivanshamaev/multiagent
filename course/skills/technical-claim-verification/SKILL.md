# Technical Claim Verification

Read the lecture plan, technical requirements and current editorial findings. Enumerate substantial
claims: definitions, invariants, causality, API/version details, numbers and implementation status.
For each record location, assertion, source anchor, scope/date and verification disposition.

Use primary documentation/original papers for general claims. Implementation examples require
repository code and dated evidence: a proposal in init is not implementation evidence. Offline
invariants, historical live samples and not-implemented extensions are distinct. Do not infer
model quality from unit-test PASS, exactly-once effects from checkpoints, or authority from prompts.

Verify active external API/version/pricing details online. If sources are unavailable, narrow or
remove the claim or record unresolved uncertainty; remembered behaviour is not verification.
Separate article claims, local observations and the author's synthesis. Attribute reused concepts.

Compare diagrams with actors, messages, branches and trust boundaries described in prose/code.
Validate minimal illustrative code without production writes or paid calls. Renderer checks and
human visual review are separate gates, not results inferred from fenced source.

Record findings, corrections and a recheck against source anchors. Major corrections trigger
editorial reread. Use the repository review schema, checked input hashes and this skill's version;
unresolved blocking findings prevent completion. Same-author passes are not independent review.
This skill authorizes read-only verification, not deployment, publication, paid calls or delegation.
