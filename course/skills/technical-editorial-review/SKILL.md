# Technical Editorial Review

Read the lecture's todo plan, course technical requirements, glossary and adjacent primary-owner
outlines before reviewing. Preserve the requested depth: deep theory, no student labs or setup.
Review the complete draft in a separate pass after authoring, including captions and conclusions.

Check definitions before use, causal continuity, explicit assumptions, counterexamples and clear
distinctions between facts, design rationale and hypothetical extensions. Avoid adding detail
owned by another lecture: cross-link its primary owner instead. Repeated cases require a new
analytical question, not another introduction. Compare internal sections and neighbouring topics.

Check Russian language, unnecessary anglicisms, stable role/state names and transitions between
sections. Diagrams must answer a question and agree with prose; a textual source check does not
prove visual readability. Record render review separately when a renderer is available.

Use the repository's review template. Findings contain location, severity, rationale, disposition
and resolution. Reread corrected sections; major restructuring requires another full pass.
An editorial pass is not technical verification or independent review if performed by the author.
Record checked input hashes and this skill's version. Never mark a missing/stale review as passed.
Do not publish, install tools, call paid models or delegate solely because this skill is active.
